## 2026-07-28 — 지도 탭(정복맵) 구현 노트

지도 탭 3.1절 실제 구현 완료. 드릴다운 대신 자유 팬/줌 채택, 다중 섬 지역 렌더링 규칙 확정, `group_members` RLS 무한 재귀 버그 발견 및 수정.

**기능별 진행 상태**
- 기능 1 (정복맵 렌더링): ✅ 완료
- 기능 2 (그룹 선택): ✅ 완료 — `GroupSubTabSelector` 위젯, 피드 탭과 공유 가능한 형태로 구현
- 기능 3 (지역 탭 인터랙션): ✅ 완료
- 기능 4 (확대/드릴다운): ⏸️ 이번 범위에서 제외, 아래 "원안과 달라진 점" 참고
- 기능 5 (친구/그룹 관리 진입): 미착수 (다음 단계)
- 기능 6 (전국 라멘집 검색): 🟡 부분 구현 — 검색창에서 검색 실행 + 결과 탭 시 기록하기로 이동까지만 구현. 검색 결과로 지도 확대 이동/하이라이트, 기 방문 매장이면 바텀시트로 바로 연결하는 부분은 아직 미구현

**원안과 달라진 점**
- **드릴다운 대신 자유 팬/핀치줌**: 시/도 탭 → 시/군/구 확대라는 원안 대신, `InteractiveViewer`로 사용자가 원하는 곳을 직접 확대/이동하는 방식으로 구현. 최소 배율은 전국 지도가 화면에 꽉 차는 수준, 최대 배율은 폴리곤 하나가 화면을 다 채우지 않는 선으로 제한. "탭 한 번으로 특정 시/도까지 부드럽게 이동"하는 애니메이션형 드릴다운은 다음 단계 후보로 남김
- **렌더링 방식**: CustomPainter/컬링 없이 지역마다 `ClipPath` 위젯 하나로 그리는 가장 단순한 방식 채택 (256개 시/군/구 규모에서 성능 문제 없음)
- **다중 폴리곤 파트 처리(신규 이슈 발견 및 해결)**: 신안군·완도군·옹진군처럼 섬이 많은 지역은 모든 파트를 다 그리면 점처럼 흩어져 보이는 문제가 있어 처음엔 "가장 큰 파트 1개만" 그리도록 단순화했었음. 그런데 **안산시단원구(본토 54km² + 대부도 46km²로 비슷한 크기 두 덩어리)**에서 큰 섬이 통째로 빠지면서 지도 한가운데 구멍이 생기는 부작용을 발견 → **면적 기준 상위 2개 파트까지 렌더링**하는 것으로 최종 확정. 정복 집계(주소 문자열 매칭)는 폴리곤 렌더링과 무관하게 항상 정확함
- **색상 토큰 추가**: 미정복 지역 폴리곤에 원안대로 `MenlogColors.surface`(#F5D9B8, 검색창/헤더 아이콘 배경과 공용)를 그대로 쓰니 배경(#EDE0CC)과 명도 차이가 작아 지도 모양이 잘 안 보임 → 지도 전용 색상 `MenlogColors.mapUnconquered`(#C9B896)를 신설해서 분리
- **지역명 라벨 미표기**: 전국 축소 지도에서는 시/군/구가 너무 작아 폴리곤 위에 직접 라벨을 표기하지 않음. 지역명은 바텀시트 제목으로만 노출 (드릴다운 도입 시 재검토)
- **`regionCode`는 DB에 저장하지 않음**: 기획서 5.2절 "공통 모듈 설계"에는 `RamenShopSearchRepository` 결과에 `regionCode`를 저장/보관하는 것처럼 적혀 있으나, 실제로는 **지도 조회 시점마다 매장 주소(`ramen_shops.address`)를 시/군/구 경계 GeoJSON과 문자열 매칭해서 즉시 계산**하는 방식으로 구현(`RegionMatcher`). 동명 지역(예: "중구"가 여러 시/도에 존재)은 시/도 축약형까지 함께 매칭해서 구분. 저장 컬럼 추가 없이 처리되므로 데이터 모델 변경 불필요
- **행정구역 경계 데이터 출처 확정**: 공공데이터포털 대신 [vuski/admdongkor](https://github.com/vuski/admdongkor)(SGIS 통계지리정보서비스 기반 가공 데이터, CC BY 4.0) 저장소의 GeoJSON을 Douglas-Peucker로 단순화해서 앱 자산으로 포함(`assets/data/sig_boundaries.geojson`). 라이선스상 앱 내 출처 표기 유지 필요

**DB 버그 — `group_members` RLS 무한 재귀**
- 실제 로그인 계정으로 처음 테스트했을 때 지도 탭 로딩이 항상 실패하는 버그 발견. 원인은 `group_members` SELECT RLS 정책이 **자기 자신(`group_members`)을 서브쿼리로 다시 참조**하는 구조라, Postgres가 무한 재귀로 판단해 에러(`42P17: infinite recursion detected in policy`)를 던지는 것이었음
- **로그인 안 한 상태(그룹 조회 자체가 없음)에서는 이 정책이 실행될 일이 없어서 지금까지 발견되지 않았던 잠복 버그** — CLAUDE.md 초기 스키마 설계 단계부터 있었던 문제
- **해결**: `SECURITY DEFINER` 함수 `is_group_member(group_id, user_id)`로 멤버십 체크를 감싸서, 함수 내부 쿼리가 RLS를 우회하도록 함. `group_members`/`groups`/`visits`의 관련 SELECT 정책을 모두 이 함수를 쓰도록 통일(마이그레이션: `supabase/migrations/20260728_fix_group_members_rls_recursion.sql`)
- ⚠️ **기획서 4장 "피드 좋아요/댓글" 신규 테이블의 RLS 정책을 작성할 때, `group_members`를 서브쿼리로 직접 다시 참조하지 말고 반드시 `is_group_member()` 함수를 재사용할 것** — 그렇지 않으면 동일한 무한 재귀 버그가 재현됨
